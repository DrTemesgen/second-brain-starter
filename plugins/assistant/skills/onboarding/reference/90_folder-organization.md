# Module 90 — Folder & File Organization

Writes `me/folder-map.md` — the file that makes "Claude decides where
things go" actually deterministic instead of a fresh guess every time.

## Topics to cover

- **Destination roots** — using what Module 50 already surfaced about
  their work domains, ask where each one should actually live on disk (or
  cloud-drive equivalent). One root per major category is a reasonable
  default shape, but let them set their own.
- **Naming conventions** — Title Case vs. lowercase, how specific vs.
  general folder names should be, anything they already do consistently
  that's worth writing down as a rule rather than relying on habit alone.
- **The "existing folder beats new folder" rule** — confirm they want this
  (almost everyone does once it's explained: prevents duplicate near-
  identical folders accumulating over time).
- **Inbox/triage mechanism** — do they want a designated catch-all folder
  for ambiguous or one-off items, revisited periodically? A dated-subfolder
  convention (`_Inbox\YYYY-MM-DD <short name>`) is a reasonable default to
  offer.
- **The "always announce the path" convention** — confirm this: every time
  Claude creates something, it states the full path back as a clickable
  link, so nothing gets filed somewhere they have to go hunting for.
- **Known mess** — do they already have folder clutter worth flagging for
  a future cleanup pass? Capture it as a punch-list, not something to
  touch now (Constitution Article 6 — offer, don't act unasked).

## What gets written

Fill `me/folder-map.md` completely: the destination-roots table from their
real answers, routing heuristics (adjust the shipped defaults only if they
want something different), and the known-mess list if they have one.
