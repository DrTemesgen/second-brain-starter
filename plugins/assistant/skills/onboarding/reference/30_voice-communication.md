# Module 30 — Voice & Communication

Writes `me/voice.md`. Used by the `writer` agent and by any drafting Claude
does on the user's behalf — this is what keeps output from reading as
generic AI-voice.

## Topics to cover

- **Does the user write differently for different audiences?** Don't
  presuppose registers like "visionary founder" or "formal institutional"
  — ask them to name their own real audiences (could be one, could be
  several: a boss, a professional network, close friends, a public
  audience, clients).
- **Per register:** tone, structure conventions, specific words or phrases
  to avoid, and — if useful — a real or paraphrased example opening line
  that sounds like them.
- **Typo/grammar handling** — same question as Module 10 but specifically
  for drafted output: fix silently, or flag?
- **Banned words/phrases** — AI-writing tells they want avoided
  specifically (common ones: certain stock transition phrases,
  corporate-speak, excessive hedging — but ask what actually bothers
  *them* rather than reciting a generic list).
- **Canonical bio** — one line, quotable as-is, for someone else to use
  introducing them.
- **Quality bar** — ask them to describe, in their own words, how they'd
  know a draft actually sounds like them vs. sounds like "AI wrote this."
  Write that description down verbatim if possible; it's more useful than
  a generic gut-check question.

## Interview notes

If they say "I only write one way, no registers" — that's a complete,
simpler answer. Don't manufacture multiple registers they don't use.

## What gets written

Fill `me/voice.md` — one `### {{REGISTER_NAME}}` block per real register
they named, universal rules section, canonical bio, and their own
quality-bar phrasing.
